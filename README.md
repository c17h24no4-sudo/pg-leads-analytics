# pg-leads-analytics

Учебный проект: аналитика воронки лидов на **PostgreSQL**, весь расчёт на SQL (представления), поверх — небольшой API на FastAPI и тесты на настоящей базе.

Зачем: показать, что отчёты считаются в базе, а не в Python, и что они проверены тестами.

## Что внутри

| Файл | Что делает |
|---|---|
| `sql/schema.sql` | таблицы `managers`, `leads`, `stage_events`, ограничения (`CHECK`, `UNIQUE`, внешние ключи), индексы |
| `sql/views.sql` | пять представлений: воронка, время в стадиях, конверсия по источникам, рейтинг менеджеров, лиды по дням |
| `app/seed.py` | детерминированные тестовые данные (400 лидов, `seed=7`) |
| `app/api.py` | `GET /stats/{funnel,sources,managers,daily}` и `GET /leads` с фильтром и пагинацией |
| `tests/test_reports.py` | 8 тестов на реальном PostgreSQL 16 |

## SQL-приёмы, которые здесь используются

- **CTE** (`WITH`) — воронка и рейтинг менеджеров;
- **оконные функции** — `lead() OVER (PARTITION BY …)` для времени в стадии, `rank()` и `sum() OVER ()` для рейтинга и доли, скользящее среднее за 7 дней через рамку `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`;
- **`FILTER (WHERE …)`** для условных агрегатов;
- **`generate_series`**: дни без лидов попадают в календарь, иначе окно «7 строк» растянулось бы больше чем на 7 дней;
- параметризованные запросы в API: фрагмент SQL в параметре `source` трактуется как обычная строка (есть тест).

## Запуск

```bash
docker compose up -d                       # PostgreSQL 16 на порту 5434, схема и представления загружаются сами
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python "psycopg[binary]" fastapi uvicorn pytest httpx
.venv/bin/python -m app.seed               # заполнить тестовыми данными
.venv/bin/python -m pytest -q              # 8 тестов
.venv/bin/uvicorn app.api:app --port 8020  # http://localhost:8020/docs
```

Строка подключения берётся из `DATABASE_URL` (по умолчанию `postgresql://leads:leads@localhost:5434/leads`). Если база недоступна, тесты пропускаются с понятным сообщением.

## Пример результата (seed=7)

Воронка: 400 новых → 266 квалифицированных (66,5 %) → 154 с предложением (38,5 %) → 90 оплат (22,5 %).
Лучшая конверсия у источника `referral` (34,8 %), худшая у `ads` (8,6 %).

## Что не сделано

Данные синтетические, это не боевая система. Нет миграций (схема применяется при старте контейнера), нет аутентификации в API, ClickHouse не использовался (только PostgreSQL).
